# Tsuzuri（綴）

**1つの Markdown ファイルを、ノートの木として書き・組み替えるための Windows 用エディタ。**

Notion のようにサブページを掘っていけます。ただし、サブページのために別のファイルは作りません。
ページはすべて1つの `.md` の中に収まり、中身は標準の Markdown のままです。
このソフトが無くなっても、データはただの `.md` として読めます。

Windows 用のデスクトップアプリ（WPF / .NET Framework 4.8）です。

> 開発中です。細かい仕様は [SPEC.md](SPEC.md)、動作確認の状況と積み残しは [TODO.md](TODO.md) にあります。
> 画面の文字と文書は日本語だけです。

---

## 何が違うのか

### 1. サブページは別ファイルにしない

サブページを作るたびに新しいファイルを作ると、ファイル名の決め方、使わなくなったファイルの掃除、リンク切れ、相対パスの解決が付いてきます。
Tsuzuri は、**1つのファイルの中に印を置いてページを区切ります。**

```markdown
# 親ページ

詳細は [設計](#p1) を参照。

<!--page: p1-->
## 設計
本文本文
```

- `<!--page: ID-->` の行から次の印までが、1つのページになる
- ページへのリンクは、普通の Markdown のリンク `[表示名](#ID)` で書く
- 印は HTML のコメントなので、ほかのツールで開けば1本の文書として普通に読める

### 2. サブページ作成と解除が中心の操作

- **サブページ作成**: 選んだ範囲をサブページへ移し、その場所にリンクを残す
- **サブページ解除**: いま開いているサブページを、親の本文の元の場所へ戻す

どちらもファイルの中で印を1行足すか消すかだけなので、ファイルの作成も削除も起きません。
作成して解除すると、**1文字も変わらずに元に戻ります。** 構成を後から何度でも組み替えられます。

### 3. リンクをたどると右に積み重なる

```
起動直後             [A]
A のリンクを踏む     [A帯][B]
B のリンクを踏む     [A帯][B帯][C]
```

- サブページへのリンク先は、クリックしたページの右隣に開き、画面いっぱいに出る
- 前のページは左に縦の帯としてたたまれ、帯をクリックすればそこへ戻れる
- 並んだページは、常にリンクでつながった親子（左が親）。どこから来たのかが、いつも画面から分かる
- 別の `.md` へのリンクは、新しい画面（タブ）で開く

### 4. 記号を隠して装飾する編集面

見出しは大きく（見出し1・2は下に線を引き）、リンクは青く（サブページへのリンクは緑、見出しへのリンクは紫）表示し、`#` や `**` などの記号は画面から消します。
カーソルのある行だけは記号が戻り、そのまま書けます。プレビューと編集の画面を分けません。

### 5. 持たないものを決めている

- ファイルツリーもワークスペースも持たない（開く入口はランチャーとファイラー）
- 最近使ったファイルの履歴を持たない
- リンク切れを管理しない。ファイルを自動で削除したり移動したりしない
- キーボードショートカットはほとんど割り当てない（`Ctrl+S`、見出しを作る `Ctrl+Enter`・`Ctrl+Shift+Enter`、画面を切り替える `Ctrl+PageUp`・`Ctrl+PageDown` だけ）。
  キーマップを大きくカスタマイズしている人の邪魔をしないため。操作はマウスで完結する

## 主な機能

| 機能 | 内容 |
|---|---|
| 新規作成 | ツールバーの左端で、Markdown のファイルを作って新しい画面（タブ）で開く |
| サブページ作成 / 解除 | 選んだ範囲をサブページにする／サブページを親の本文に戻す |
| 孤立ページ | どこからもリンクされなくなったサブページを一覧にする |
| 未参照の添付 | 添付フォルダのファイルのうち、本文のどこからもリンクされていないものを一覧にする |
| アウトライン | 左の欄に、見ているページの見出しを木で出す。上の `⊟` `⊞` で、すべてたたむ・すべて開く。ドラッグで節を動かす。同じ階層の先頭の `▲` `▼` で、同じ階層の見出しを1つずつ回す。右クリックで見出しのレベル変更・削除 |
| パンくず | 本文の上に、カーソルのある見出しの道筋（「1章 › 1.2 › 手順」）を出す。押すとその見出しへ移る |
| 見出しのブックマーク | 行番号を右ボタンでダブルクリックして、その行の見出しに印を付ける。一覧のクリックでそこへ戻る |
| 見出しへのリンク | 行番号を右クリックして、その行の見出しへのリンクをコピーする。本文に貼ると、貼った場所から見たリンクになる（同じ文書なら `#見出し`、別の文書なら `相対パス#見出し`） |
| 見出しの履歴 | 左の欄の下を左右に分け、左に本文で手を入れた見出し、右にリンクで移ってきたときのリンク元を新しいものから積み、クリックで戻る。リンク元へはリンクの文字の所へ戻る |
| 検索 | ページごとに検索欄を持つ。正規表現で照合し、該当箇所を検索欄の下の左半分に一覧にする。右半分は検索語のお気に入り（ファイルごと。検索欄の ☆ で足し、押すとその語で探す） |
| 画面を増やす | ツールバーの一段下の「＋」で、同じ機能の画面をもう1つ開く。別の文書や WordPress の記事を並べて直せる。並んだタブか Ctrl+PageUp・Ctrl+PageDown で切り替え（タスクバーのボタンは1つ）、タブの × でその画面だけを閉じる。使わない画面はタブを掴んで少し動かすと「休止」し、状態だけを残せる（「終了」はアプリごと閉じる）。終了したときの画面は、次の起動で全部戻す |
| ランチャー | ファイル・フォルダ・アプリ・バッチを、固定のマス目に登録して起動する。ファイラーと一緒に、本文の上半分に重ねて出す |
| ファイラー | フォルダの中身を見て、添付にしたいファイルを本文へドラッグする |
| 添付 | ファイルのドロップや貼り付けで、文書の隣の添付フォルダ（`.ファイル名/`）にコピーしてリンクを入れる。画像は本文の中に表示する（検索欄の段の「画像」「リンク」で、画像だけ／リンクの文字だけを切り替える） |
| コードの色分け | コードブロックの中の文字列・数・コメント・括弧・記号・よく使う語・「名前:」の名前に色を付ける。言語は見分けない |
| 表エディタ | 表を押すと、Excel のような画面で編集し、Markdown の表に書き戻す |
| 図エディタ | 直線・四角・丸・文字・寸法線を描いて、図として入れる。点線・矢印・文字の背景も付けられる。寸法は mm で入れられ、図を押すと描き直せる |
| Word への書き出し | サブページを本文に展開した `.docx` を作る（下を参照） |
| 保存と変更の記録 | 保存は自分で行う（自動保存はしない）。保存のたびに、文書の変更を git で記録する（AI に経緯を読ませるため。下を参照） |
| AI の欄 | 本文の右に Claude Code の端末を出し、開いている文書を直させる（下を参照） |
| WordPress | WordPress の記事を選んで開き、直して「アップロード」で更新する。手元の `.md` から新しい記事も作れる（下を参照） |

### Word への書き出し

社外に渡す資料の下書きを作るための機能です。表紙や体裁は Word で仕上げ、PDF も Word から作ります。

- サブページや別の `.md` へのリンクは、その場所に本文を展開する（全ページを解除したのと同じ結果）。手元の `.md` は書き換えない
- 画像は、画面と同じ大きさで埋め込む
- 画像以外の添付は、本文では「※参照 見積書.xlsx」という文字にし、ファイルは `文書名_添付` フォルダにコピーする
- 見出しは Word 組み込みの「見出し 1〜6」になるので、Word の目次や PDF のしおりがそのまま使える

### AI の欄（Claude Code）

ツールバーの「AI」で、本文の右に端末の欄を出します。中で [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) を動かし、開いている文書を直させます。

- 話しかけるたびに、開いているファイル・見ているページ・カーソルの行・選んでいる文字が Claude に渡る。「この節を直して」で通じる
- 話しかけたとき、未保存の編集があれば先に保存する（Claude が最新の内容を読めるように）
- 欄の下端に、最後に渡した状態と、Claude が読むファイルのボタンを出す。Claude Code が自分で読むもの（全体とフォルダの CLAUDE.md・記憶の MEMORY.md）と、Tsuzuri が渡すもの（指示・今の状態・図の書き方・フックの設定）を段で分ける。押すと .md は Tsuzuri で（添付フォルダを作らずに）、.json はメモ帳で開く
- 会話はタブで複数持てる。次に起動したときは、前の会話のタブを戻す
- 「ここに構成図を描いて」と頼むと、図エディタ・罫線・Mermaid のどれで描くかを尋ねてくる。図エディタなら、Claude が図の JSON を書き、Tsuzuri が画像にする。出来た図は押せば図エディタで手直しできる
- SSH でサーバーにつながせるときは、exe の隣の `ssh` フォルダに、接続先の一覧 `config.txt` と鍵をまとめて置く。`config.txt` は1行1つで、鍵なら `名称 | ホスト:ポート | auth=publickey | user=ユーザー名 | keyfile=キーファイル名`、パスワードなら `名称 | ホスト:ポート | auth=password | user=ユーザー名 | passwd=パスワード`。Windows の ssh が使えるように、会話を始めるたびにエディタが `%LOCALAPPDATA%\Tsuzuri\ssh` へ写して本人だけが読める権限にする（exe が Mac の共有フォルダにあっても使える）。最初の指示でその場所と形を伝えてあり、「名称につないで」で通じる。サーバーの中を変える前には確かめてくる。このフォルダはリポジトリには入れない（パスワードを平文で置くので、置き場所の扱いに注意）
- タブの名前（#1・#2…）は claude のセッションの名前。「#2 にこの会話の要約を渡して」のように、ほかのタブの会話に頼める（Claude Code のセッション間のメッセージ。Windows では 2.1.234 以上）

Claude Code は別に入れてください（`claude` が PowerShell から動く状態）。入っていなければ、この欄は普通の PowerShell として使えます。

### 変更の記録（git）

保存のたびに、文書の `.md` を `.ファイル名/git` に git で記録します。AI が「文書がどう変わってきたか」を読み、前回の続きから助言できるようにするためです。
画面に git の部品は出しません。

git は、exe の隣の `git` フォルダに置いた [MinGit](https://github.com/git-for-windows/git/releases)（Git for Windows の最小版。zip を展開するだけ）を使います。
無ければ PATH の git を使い、それも無ければ記録しません（保存はできます）。MinGit はこのリポジトリには入っていません。

### WordPress

ツールバーの「WordPress」で記事を選ぶと、一時ファイルとして開きます。直して「アップロード」を押すと、その記事を更新します。

- **WordPress への反映は「アップロード」のボタンだけ。** 保存や AI への話しかけでは送らない
- 手元には何も残さない（一時ファイルは閉じれば消える）。正は常に WordPress。終了したときに開いていた記事は、次の起動で WordPress から読み込み直す
- 送る前に、WordPress 側で誰かが直していないかを確かめる
- 本文に貼った手元の画像は、アップロードのときにメディアへ上げ、リンクを WordPress の URL に置き換える
- 開いている手元の `.md` を、新しい記事（下書き）として作れる

接続先は、exe の隣の `wordpress.json` に書きます（初めて「WordPress」を押すと、ひな形を作ってメモ帳で開きます）。

```json
{
  "sites": [
    { "name": "mysite", "url": "https://example.com", "user": "ユーザー名", "appPassword": "xxxx xxxx xxxx xxxx xxxx xxxx" }
  ]
}
```

`appPassword` は、WordPress の「ユーザー → プロフィール → アプリケーションパスワード」で作るものです（ログインのパスワードではありません）。
**このファイルにはパスワードが入るので、人に渡したりリポジトリに入れたりしないでください**（`.gitignore` で除いてあります）。

## 動作環境

- Windows 10 以降（x64 / ARM64）
- .NET Framework 4.8
- WebView2 ランタイム（AI の欄で使う。Windows 11 には入っている）
- 任意: Claude Code（AI の欄）、MinGit（変更の記録）

## ビルド

1. Visual Studio で `Tsuzuri.sln` を開く
2. NuGet パッケージを復元する（PackageReference 方式）
3. ビルドする（`Tsuzuri\bin\Release\Tsuzuri.exe` ができる）

Mac では、XAML を除いた C# のコンパイルだけを `bash tools/check-build.sh` で確かめられます（.NET SDK が要ります）。

### WordPress の変換を変えるとき

`bash tools/wp-check.sh` で、サイトの全記事を読み（GET だけ。記事は変えません）、ダウンロード → アップロード → ダウンロードと往復させて、
送る HTML の見える文字が元と同じか、往復で変わらないかを確かめます。HTML のまま残るタグ・属性・クラスの一覧も出します。
`wordpress.json` は exe の隣のものを使います（引数で渡すこともできます）。

`git config core.hooksPath tools/git-hooks` をしておくと、`Tsuzuri/WordPress/` を変えたコミットの前に、これを自動で回し、通らなければコミットを止めます。

### 解析を変えるとき

`bash tools/parse-fuzz.sh` で、編集画面が打った段落だけを解析し直した結果が、全体を解析し直した結果と同じかを確かめます
（名前を付けた例と、文書をでたらめに書き換えては比べるのを繰り返す。既定 3000 回で2〜3分）。
`Tsuzuri/Markdown/` や、`MarkdownView` の部分解析を変えたら回してください。部分解析の判断は `tools/parse-fuzz/Program.cs` に写してあるので、そちらも合わせます。

`bash tools/struct-fuzz.sh` で、アウトラインの操作（見出しを回す・動かす・消す・レベルを変える）が文書の形を崩さないかを確かめます
（でたらめな文書に操作をかけ、見出しの並び・親・リストや引用の中か・ほかの段落が変わらないかを見る。既定 30000 文書で十数秒）。
`MarkdownView.Sections.cs` や `Tsuzuri/Markdown/` を変えたら回してください。`Sections.cs` は `tools/struct-fuzz/Port.cs` に写してあるので、そちらも合わせます。

## 設定ファイル

どれも exe と同じフォルダに置きます。持ち運べるように、`%AppData%` は使いません。

| ファイル | 中身 |
|---|---|
| `app.json` | ウィンドウの位置、仕切りの位置、前回開いていたファイル、ランチャーの登録、開いていた画面（タブ）・休止した画面・AI の会話のタブなど。自動で作る。仮想マシンで画面がちらつくときは、終了してから `"softwareRendering": true` にすると GPU を使わずに描く。`"perfLog": true` にすると、打ってから画面に出るまでの時間と、ページを移るときの時間を exe の隣の `perf.log` に書く（遅さの原因を探すため） |
| `wordpress.json` | WordPress の接続先とアプリケーションパスワード。WordPress を使うときだけ自分で書く |
| `ssh/` | AI の欄から SSH でつなぐ接続先の一覧 `config.txt` と鍵。使うときだけ自分で置く（Tsuzuri が `%LOCALAPPDATA%\Tsuzuri\ssh` に写して使う） |

文書ごとの状態（ページの並び、見出しのブックマーク、検索語のお気に入り、変更の記録）は、文書の隣の添付フォルダ `.ファイル名/` に置きます。

## 構成

```
Tsuzuri/
├ MainWindow.xaml(.cs)   画面の骨格。受け持ちごとに MainWindow.*.cs に分けている
│                        （Stack: ページの並び／Outline: アウトライン／Overlays: ランチャー／Ai: AI の欄／WordPress など）
├ Markdown/              ページの読み書き（PageDocument）、Markdig による解析、変更の記録（DocumentHistory）
├ Views/                 編集面（AvalonEdit の拡張）、ランチャー、ファイラー、端末
├ Export/                Word への書き出し
├ WordPress/             WordPress の REST API、HTML → Markdown の変換、送る HTML（WordPressHtml）
├ Ai/                    AI に図を頼まれたときに読ませる、図の書き方（drawing-format.md）
├ Terminal/              AI の欄の端末の画面（xterm.js）
└ ConPty/                AI の欄の端末で使う ConPTY（conpty.dll・OpenConsole.exe）
TableEditor/             表エディタ（WPF。本体から DLL として読み込む）
DrawingEditor/           図エディタ（WPF。本体から DLL として読み込む）
tools/                   Mac でのコンパイル確認、WordPress の変換の確かめ（wp-check）、部分解析の確かめ（parse-fuzz）、アウトラインの操作の確かめ（struct-fuzz）、コミット前のフック、アイコンの生成
sample/                  動作確認用の文書
```
